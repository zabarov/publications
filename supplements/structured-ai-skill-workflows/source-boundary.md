# Source Boundary

## Public-Safe Sources

- Public explanatory article draft: referenced as public-safe background only; local author workspace path is intentionally omitted from this package candidate.
- Public demo repository: `https://github.com/zabarov/demo-codex-skill-dev-review`
- Public future examples that contain no proprietary private-skill internals.

## Private/Internal Sources

- Private skill repositories and their raw `SKILL.md`, rules, references and operational playbooks.
- Internal thread histories, private stakeholder context, access data, logs and unpublished project data.
- Private implementation details from company repositories.

## Allowed Use Of Private Sources

Private sources may be used to derive public-safe abstractions:

- role names and responsibility categories;
- gate types;
- evidence expectations;
- handoff structure;
- workflow state transitions;
- aggregate counts and anonymized patterns.

Private sources must not be quoted or exposed unless explicitly reviewed and approved as public-safe.

## Redaction Rule

If a source includes private project names, repository names, stakeholder facts, commercial strategy, access data, private operational details or unpublished product plans, use a generalized description in the manuscript and preserve the exact source only in private project notes.
